# Test fixtures — provenance and licence

These files live in `app/src/test/resources/fixtures/` and are used by
`RealOfficeFixtureUnitTest` and `RealOfficeSuiteRoundTripTest`. They are
deliberately **independent of the application code under test**: none of them
is produced by `DocxConverter`, `OoxmlPackageEnricher` or
`SmartArtChartUtils`. Importing them therefore exercises the real parser
instead of a self-consistent round-trip.

## Documents produced by a real office suite

| File | What it contains | How it was created | Licence |
|------|------------------|--------------------|---------|
| `lo_scatter.docx` | A real Writer document: title paragraph, prose paragraph, a 3×3 table, an embedded **XY scatter chart** with two series and explicit numeric X values, header and footer. | Generated by **LibreOffice 7.4** through its UNO API (`tools/fixtures/generate_lo_fixtures.py`), then saved as `MS Word 2007 XML`. | CC0-1.0. |
| `lo_rich.doc` | A real **Word 97–2003 binary** document (OLE2): Heading 1, plain/bold/italic paragraphs, a 3×3 table, an embedded PNG, header, footer, custom margins (1800/1500/2000/1700 twips), an explicit page break and a second-page paragraph. | Generated by **LibreOffice 7.4** through its UNO API and saved as `MS Word 97`. | CC0-1.0. |
| `legacy_real.doc` | A smaller legacy Word 97–2003 binary document. | A DOCX was hand-authored, then converted with LibreOffice (`soffice --headless --convert-to "doc:MS Word 97"`). | CC0-1.0. |

`lo_scatter.docx` and `lo_rich.doc` are the fixtures that prove behaviour
against a *different producer*: the OOXML chart in `lo_scatter.docx` is written
by LibreOffice, not by this project, and the `.doc` is a genuine binary Word
file rather than a renamed DOCX.

## Known limitation: no Word-authored SmartArt fixture

LibreOffice has **no SmartArt authoring support**: it can render an imported
SmartArt as a group of shapes, but it cannot create `word/diagrams/*` parts, and
re-exporting a document that contained SmartArt does not reproduce the original
DrawingML diagram package. Microsoft Word is proprietary and no permissively
licensed Word-authored SmartArt `.docx` was found in the public corpora that
were checked (docx4j, Apache POI test data, `superdoc/docx-corpus`).

Consequently `smartart_real.docx` remains a **specification-conformance**
fixture: it is valid ECMA-376 and independent of this project's writer, but it
was not emitted by Word. It proves that the parser handles real diagram parts,
`dgm:cxn` relations and `dgm:pt modelId` values, not that it round-trips every
exotic SmartArt layout Word can produce. This limitation is stated here rather
than hidden. The chart and legacy-DOC paths do have genuine office-suite
fixtures (`lo_scatter.docx`, `lo_rich.doc`).

## Regenerating

```bash
# Hand-authored OOXML fixtures
python3 tools/fixtures/generate_fixtures.py

# Real LibreOffice fixtures (requires python3-uno + libreoffice-writer/calc)
python3 tools/fixtures/generate_lo_fixtures.py
```

Both generators are checked in and the resulting files are committed so the
test suite never depends on LibreOffice being installed.

## Why this matters

A test that exports with `DocxConverter` and then imports with the same
`DocxConverter` can pass even when both sides share the same bug. These
fixtures are authored from the specification and, for the chart and `.doc`
paths, by a different producer entirely, so a passing import proves that the
parser understands third-party-shaped OOXML rather than only its own output.
